# Codex 완료 전 코드 품질 검토

`Stop` 훅이 같은 Codex 대화에 검토 지시를 전달합니다. 코드·스크립트·동작 설정을 실제로 변경한 구현 요청이면 요구사항, AI 슬롭, 과잉 설계와 중복 구현을 점검하고 근거 있는 문제만 수정·검증합니다. 별도 모델·API 키·패키지 설치는 필요하지 않습니다. Node.js를 사용합니다.

## 동작과 범위

- 처음 종료를 시도하면 `REVIEW.md`를 continuation 지시로 전달합니다.
- 모델이 원래 요청과 작업 내역으로 적용 여부를 판단합니다. 설명·조사·읽기 전용 리뷰·문서만 변경한 작업·답변/승인 대기는 검토와 수정을 건너뜁니다.
- `stop_hook_active: true`이면 `{}`를 반환하여 이 훅의 추가 검토 요청을 막습니다. 다른 Stop 훅의 반복까지 제어하지는 않습니다.
- 쉘 명령 문자열이나 불안정한 transcript 형식으로 수정 여부를 추측하지 않습니다. 따라서 검토 대상이 아닌 일반 대화도 적용 여부를 판단하는 추가 continuation이 한 번 발생할 수 있습니다. 검토·수정과 후속 검증에는 추가 시간과 모델 사용량이 발생합니다.
- 자동 검토는 같은 AI의 판단이며 모든 문제의 발견·수정을 보장하지 않습니다. 승인이나 사용자 답변을 대신하지 않습니다.
- 입력 오류나 지침 파일 누락은 경고로 표시하며 반복하지 않습니다. 이 경우 자동 검토가 수행됐다고 간주하지 않습니다.

검토 기준은 [REVIEW.md](REVIEW.md)에서 관리합니다. `AGENTS.md`에는 작성 시 필요한 최소 구현·재사용·업무 규칙·사용자 작업 보존 원칙을 유지합니다. 이 훅은 Codex 전용이므로 다른 에이전트에는 별도 설정이 필요합니다.

## 설치

기존 전역 `~/.codex/hooks.json` 전체를 백업하고 아래 명령이 출력한 `hooks.Stop` 그룹을 기존 이벤트와 핸들러를 유지하며 병합합니다. 전역과 프로젝트에 같은 훅을 중복 등록하지 마세요.

```sh
node hooks/code-quality-review/code-quality-review.mjs --print-config
```

생성 설정에는 현재 Node 실행 파일과 스크립트의 절대 경로가 들어갑니다. 저장소나 Node 경로를 변경하면 다시 생성하세요. Windows에서는 공백이 있는 경로도 `cmd.exe`에서 실행할 수 있도록 전체 명령과 각 경로를 따옴표로 감쌉니다. 생성된 따옴표를 제거하지 마세요.

Windows의 `%` 포함 경로는 `cmd.exe`의 환경변수 확장을 안전하게 막을 수 없어 지원하지 않습니다. 해당 문자가 Node 또는 스크립트 경로에 있으면 설정 생성이 stderr 메시지와 종료 코드 `1`로 실패하며 JSON은 출력하지 않습니다. `%`가 없는 경로로 옮긴 뒤 다시 생성하세요. `--print-config`의 인자가 잘못된 경우에도 설정 파일을 갱신하지 말고 오류를 먼저 해결하세요.

Codex CLI의 `/hooks`에서 새 Stop 훅의 출처·명령을 검토하고 신뢰 등록한 뒤 새 대화에서 실제 동작을 확인하세요. 신뢰 상태를 수동으로 만들어 넣거나 검토 우회 옵션을 일상 설정에 추가하지 마세요. 훅 정의가 바뀌면 다시 신뢰 등록이 필요합니다. `REVIEW.md`만 바꾼 경우에도 내용은 별도로 검토해야 합니다.

## 검증과 해제

```sh
node --test hooks/code-quality-review/code-quality-review.test.mjs
node --check hooks/code-quality-review/code-quality-review.mjs
```

자동 검증은 현재 테스트를 실행하는 Node를 사용해 첫 Stop의 검토 지시, 재진입 종료, 오류 경고, 설정 생성과 셸 실행을 검사합니다. Windows에서는 공백이 있는 Node·스크립트 경로도 실행합니다. macOS·Linux에서는 `/bin/sh`로 생성된 명령을 실행합니다. 실제 Codex 적용은 새 대화에서 작은 코드 변경을 요청해 추가 검토가 한 번 수행되는지, 조사 요청과 승인 대기에서 수정하지 않는지 확인해야 합니다.

해제하려면 `/hooks`에서 이 훅만 비활성화하거나 `hooks.json`의 해당 Stop 그룹만 제거합니다. 시크릿 검사 등 다른 훅과 `features.hooks`는 유지합니다.

공식 계약: [Hooks](https://learn.chatgpt.com/docs/hooks).
