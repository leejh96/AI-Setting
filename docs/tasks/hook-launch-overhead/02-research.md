# Windows 훅 실행기 시작 비용 조사

2026-10-26 기준 Windows, Node.js 24.14.0, Antigravity CLI 1.4.6에서 확인했다. 저장소의 지원 기준인 Node.js 22 이상은 변경하지 않는다.

## 질문과 제약

Antigravity 품질 훅의 바깥 PowerShell 프로세스 시작 비용을 줄이면서 경로의 문자 보존, 표준 입출력 계약, 준비 후 감시 유지, 기존 오류 처리를 유지할 수 있는가?

감시 워커를 시작하는 내부 `Start-Process`는 유지한다. 기존 Windows 재현에서 단순 detached 실행은 출력 파이프를 남겼다. 시크릿 검사 훅과 모델 호출 정책도 변경하지 않는다.

## 출처와 호환성

- Context7로 Node.js 22의 공식 `child_process` API와 Antigravity 문서를 조회했다. Antigravity 검색 결과만으로 훅 명령의 Windows 토큰화를 확인할 수 없어 공식 훅 문서도 직접 읽었다.
- [Node.js 22 child_process](https://nodejs.org/docs/latest-v22.x/api/child_process.html): 실행 파일과 인자 배열, `shell`, `stdio`, `detached`, `windowsHide`의 계약을 확인했다. 새 런타임이나 라이브러리는 추가하지 않는다.
- [Antigravity 훅 문서](https://www.antigravity.google/docs/hooks): `command`는 문자열이며 입력·출력은 JSON 표준 입출력이다. 전역 설정은 `~/.gemini/config/hooks.json`이다. 문서에는 Windows 인용 처리의 세부 구현이나 별도 인자 배열이 명시되어 있지 않다.
- 로컬 `agy --version`·`--help`, 실제 전역 등록 내용, 기존 명령 생성 테스트와 Windows 파이프 재현 기록을 함께 확인했다. 버전 변경이나 설치 작업은 수행하지 않았다.

## 확인된 사실과 측정

- 로컬 품질 훅의 두 등록 명령은 변경 전 생성기 출력과 정확히 일치했다. 활성화 상태·타임아웃·다른 훅은 수정 대상이 아니다.
- 같은 Stop 입력을 새 프로세스로 반복 실행했다. 백그라운드 작업이 남아 즉시 빈 JSON을 반환하는 입력으로 실행기 시작 비용을 분리했다. 중앙값은 PowerShell 경유 371ms, 직접 Node 실행 101ms였다. 이는 모델 검토나 전체 작업 완료 시간의 측정이 아니다.
- 직접 실행과 cmd 실행, 직접 준비 후 출력 종료·감시 유지, 공백·작은따옴표·특수문자·한글 경로의 기존 실행기 유지를 검사하는 5개 테스트가 통과했다.
- 전체 Antigravity 회귀 테스트는 30개 중 29개 통과, Windows Git sh를 따로 지정해야 하는 macOS 형식 시험 1개는 건너뛰었다. 수정 감지, 검토 재요청과 5회 상한, 종료 표식, 감시 실패 경고도 통과했다.
- 전역 파일 전체와 원래 권한을 접근 제한된 백업 폴더에 보존한 뒤, 예상한 기존 명령과 일치하는 `PreInvocation`·`Stop` 명령 두 개만 갱신했다. 다른 설정의 의미와 원래 파일 권한이 보존됐음을 확인했다. 원자 교체 후 권한 차이가 생긴 시도는 복구하고, 최종 적용에서는 원래 권한을 재적용해 일치를 확인했다.
- 갱신된 전역 명령을 직접 읽어 합성 입력으로 실행했다. 준비 출력 `{injectSteps: []}`, 준비 프로세스 종료 후 감시 생존, 코드 수정 없는 Stop의 `unchanged` 종료와 검토 요청 0회를 확인했다. 실제 모델 호출은 없었다. 이 단일 시험의 준비 925ms·Stop 181ms는 감시·상태 처리까지 포함하므로 앞선 시작 비용 비교와 구분한다.

## 판단과 적용 기준

문서에 없는 새 설정 필드를 도입하지 않는다. Node·훅 경로가 모두 ASCII 영숫자와 `_ : / . -`로만 구성된 드라이브 절대 경로일 때만 따옴표 없는 명령을 생성한다. 공백, 한글, 셸 특수문자, UNC 등 다른 경로는 기존 UTF-16 EncodedCommand를 유지한다.

직접 명령은 단순 공백 분리와 cmd 양쪽에서 같은 인자를 전달한다는 로컬 검증에 근거한다. 이를 Antigravity의 모든 버전에 대한 토큰화 보장으로 확대하지 않는다.

## 남은 확인

- 이미 실행 중인 Antigravity 앱의 설정 재읽기와 실제 UI·모델 대화는 확인하지 않았다. 새 세션에서 활성 상태와 동작을 확인해야 한다.
- 실제 macOS 실행과 다른 Antigravity 버전의 명령 해석은 확인하지 않았다. macOS 명령 생성과 특수 Windows 경로의 기존 실행 방식은 유지했다.

리뷰어 판단 기준: 단순 경로의 바깥 실행기만 줄이고, 특수 경로 처리와 감시 프로세스의 독립 실행은 유지한다. 원본 설정과 다른 구조·명령이면 자동으로 덮어쓰지 않는다.
