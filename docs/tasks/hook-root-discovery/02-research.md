# 여러 작업 폴더의 Git 루트 조회 비용

2026-10-26 Windows, Node.js 24.14.0에서 조사했다. 저장소의 Node.js 22 이상 지원 기준과 기존 감시·검토 정책은 유지한다.

## 질문과 제약

Codex·Antigravity 공통 감시 준비에서 Git 루트 조회를 최대 두 개씩 병렬 실행해도 기존 범위, 입력 순서, 실패 판정과 출력 제한을 유지할 수 있는가?

프로젝트 파일 내용은 읽지 않는다. `git -C <cwd> rev-parse --show-toplevel`과 `GIT_OPTIONAL_LOCKS=0`을 유지한다. 조회 결과의 중복 루트 제거는 그대로 두며, 상위 저장소가 확인됐다고 하위 폴더의 별도 저장소 조회를 생략하지 않는다. 새 패키지·상주 프로세스·전역 설정은 추가하지 않는다. 한 준비 요청에서 동시에 실행하는 Git 조회는 기존 한 개에서 최대 두 개로 늘어난다.

## 출처와 호환성

- Context7의 Node.js 22 문서를 먼저 조회해 `execFile`의 콜백, timeout, maxBuffer, killSignal, shell 기본값을 확인했다. [Node.js 22 API](https://nodejs.org/docs/latest-v22.x/api/child_process.html)는 직접 웹 접근이 실패해 공식 소스도 확인했다.
- Context7 요약에는 `spawnSync`가 비정상 종료마다 예외를 던진다는 부정확한 설명이 있었다. 이 설명을 채택하지 않고 반환 상태와 오류를 공식 소스·실행 결과로 확인했다.
- [Node.js 22.17.0 child_process.js](https://github.com/nodejs/node/blob/v22.17.0/lib/child_process.js): `execFile`은 종료 코드, killed, signal을 콜백 오류에 담는다. 시간 초과 시 파이프를 닫고 지정 신호를 보낸다. 기본 maxBuffer는 1MiB이며 비동기 출력 제한은 각 스트림에 적용된다.
- [Node.js 22.17.0 spawn_sync.cc](https://github.com/nodejs/node/blob/v22.17.0/src/spawn_sync.cc): 동기 실행은 출력 바이트의 합계에 제한을 적용한다. 초과는 ENOBUFS, 시간 초과는 ETIMEDOUT이다.
- 로컬 Node.js 24의 내장 구현과 실제 프로세스에서도 같은 오류 차이를 재현했다. Node.js 22에서의 실제 실행은 확인하지 않았으며, 사용한 API는 22에서 제공된다.

## 확인한 동작과 측정

- 실제 Git 루트 조회를 전후 교차 실행하고 처음 두 회를 제외한 각 여섯 표본의 중앙값을 비교했다. 한 폴더는 순차 76ms·병렬 75ms, 여덟 폴더는 순차 601ms·병렬 352ms였다. 이는 조회 구간이며 감시 실행기 시작·probe·모델 검토는 포함하지 않는다.
- 한 임시 Git 저장소의 하위 폴더들에서 변경 전 HEAD와 최종 코드를 번갈아 실행해 준비 전체 구간도 측정했다. 각 다섯 표본의 중앙값은 한 폴더 851ms→849ms, 여덟 폴더 1,366ms→1,126ms였다. 숨김 워커 실행과 준비 상태·probe 확인까지 포함하며, 모든 준비 후 수정 없는 종료를 확인했다. 모델 응답 시간은 포함하지 않는다.
- stdout·stderr에 각각 600KiB를 쓰면 동기 실행은 ENOBUFS였지만 비동기 기본 제한은 통과했다. 각각 500KiB는 둘 다 통과했다. 단순히 API만 바꾸면 기존 제한이 달라진다.
- 비동기 조회도 원본 Buffer로 받아 두 스트림의 합계가 1MiB를 넘으면 종료한다. 이를 ENOBUFS로, 타임아웃은 ETIMEDOUT으로 기록한다. Git 미설치와 정상적인 비영 종료의 작업 폴더 감시 전환은 기존 정책을 유지한다. 그 밖의 실행 오류는 준비 실패다.
- 한 배치의 모든 조회 콜백이 끝난 뒤 결과를 입력 순서대로 처리한다. 하나라도 실패하면 다음 배치를 시작하지 않는다. 결과 캐시는 만들지 않는다.
- 관련 테스트 12개가 통과했다. 실제 Git이 있는 폴더·없는 폴더·중첩 저장소·중복 루트, 병렬 상한, Git 미설치, EIO와 불명확 오류, 시간 초과, 단일·합산 출력 초과, 잘못된 UTF-8의 원본 바이트 계산, 실패 후 프로세스 종료와 실패 기록 보존을 확인했다.
- 전체 품질 훅 회귀는 156개 중 154개 통과, 별도 Windows Git sh 경로가 필요한 macOS 형식 시험 2개는 건너뛰었다. Codex·Antigravity의 변경 감지, 감시 실패와 복구, 검토 예산, 종료 표식과 명령 실행을 확인했다.

## 판단과 남은 확인

조회 비용이 폴더 수에 비례하므로 제한된 병렬 실행을 적용한다. 두 개를 넘는 병렬 실행이나 저장소 경로 캐시는 도입하지 않는다. 감시 워커의 Windows 숨김 실행, 변경 추적, 검토 예산과 종료 표식 처리는 유지한다.

실제 앱 화면·모델 대화와 macOS 실행은 이번 로컬 조회 시험에 포함하지 않는다. 리뷰어는 API 이름이 같은 제한을 보장한다고 가정하지 말고, 합산 원본 바이트 제한과 배치 실패 시 다음 조회가 시작되지 않는지 확인해야 한다.
