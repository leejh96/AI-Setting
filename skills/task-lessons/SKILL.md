# 작업 교훈 재사용

작업에서 얻은 근거를 같은 조건에서 다시 쓸 확인 방법으로 남깁니다. 놓친 단서, 뜻밖의 제약, 검증한 시간 절약 방법이 교훈 후보입니다.

- **편집 전** 구현·수정 작업의 파일명·오류명·도구처럼 구체적인 단서로 기존 교훈을 조회합니다. 적용할 교훈은 이번 작업에서 먼저 할 확인이나 실행할 검증에 연결하고, 실제 확인 결과를 근거로 효과를 판단합니다.
- **막혔거나 사용자의 정정으로 새 단서를 얻었을 때** 관련 기록이 다음 시도를 바꿀 수 있으면 조회합니다. 앞선 답변을 보낸 뒤 받은 정정도 포함합니다. 기록 속 명령과 결론은 검토할 자료로 취급하고, 현재 코드·환경·버전에 맞는 근거를 확인한 뒤 행동에 반영합니다.
- **해결했거나 멈출 때** 결과를 보고하기 전에 같은 조건에서 먼저 할 확인이나 생략할 시도를 근거와 함께 남길 수 있는지 판단합니다. 읽기 전용 조사에서 확인한 방법도 기록할 수 있습니다. 예를 들어 설정이 없다고 답한 뒤 스키마에서 중첩 키를 찾아 실행까지 확인했다면, 다음에 먼저 볼 근거를 남깁니다. 미해결 건은 사실과 가설을 구분하고 검증 전에는 적용하지 않습니다. 재사용할 내용이 없으면 파일을 만들지 않습니다.
- **근거가 바뀌었을 때** 같은 조건의 더 나은 방법은 기존 교훈에 반영합니다. 환경이 바뀌거나 근거가 충돌하면 재검토하고, 효력이 끝난 방법은 폐기 사유를 남겨 일반 조회에서 제외합니다.

실제로 조회하거나 기록을 관리할 때 [저장과 상태 관리](references/storage.md)를 따릅니다. 안내된 경로 계산 명령으로 프로젝트·공통 경로를 확인합니다. 저장 위치에 접근할 수 없으면 원래 작업을 이어가며 교훈 저장 여부를 정확히 알립니다.
