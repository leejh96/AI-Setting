# 저장과 상태 관리

## 경로 결정

프로젝트 디렉터리에서 아래 명령으로 `project`와 `shared` 경로를 확인합니다. `project`는 현재 프로젝트용 경로입니다. 경로를 계산하는 단계는 디렉터리를 만들지 않습니다.

- Windows PowerShell에서는 `& '<이 스킬의 절대 경로>/scripts/location.ps1'`를 실행합니다. Node.js가 자식 프로세스 출력을 캡처할 수 없는 Windows 샌드박스에서도 PowerShell이 Git 출력을 직접 읽습니다.
- 다른 환경에서는 `node '<이 스킬의 절대 경로>/scripts/location.mjs'`를 실행합니다.

기본 루트는 `$CODEX_HOME/task-lessons`이며 `CODEX_HOME`이 없으면 `~/.codex/task-lessons`입니다. 기존 교훈 저장소가 확인되고 같은 구조라면 `CODEX_LESSONS_DIR`에 해당 절대 경로를 지정해 재사용합니다. 다른 구조라면 위치와 프로젝트 대응 관계를 확인해 기존 기록을 조회합니다. 이전이나 삭제가 필요하면 대상과 이유를 먼저 정리합니다. 검증에서는 `CODEX_LESSONS_DIR`에 전용 임시 경로를 지정합니다.

프로젝트 키는 Git `origin`으로 계산합니다. `github.com`의 표준 HTTPS와 `git` 사용자 SSH 주소는 같은 소유자·저장소 경로를 공유합니다. 일반 서버는 전송 방식과 경로를 구분하며, SSH에서는 사용자와 상대·절대 경로도 구분합니다. 비밀 인증값은 키에 넣지 않습니다. URL만으로 원격을 안전하게 식별할 수 없으면 Git 공용 디렉터리를 사용합니다. 로컬 Git 원본을 복제했다면 원본을 따라가고, Git 프로젝트가 아니면 지정한 작업 디렉터리를 기준으로 합니다. 원격의 별칭이나 전송 방식이 달라지면 같은 저장소의 복제본도 서로 다른 키를 얻을 수 있습니다.

## 조회

1. 작업에서 확인한 단서 중 교훈의 제목이나 본문에 나올 검색어를 최대 5개 고릅니다. 첫 조회 범위는 `project`의 `*.md` 파일로 한정합니다. 검색 전에 경로를 확인하고, 부재가 확인되면 해당 범위에 기록이 없는 것으로 봅니다. 예를 들어 `rg -l -i -F -g '*.md' -e '<작업 대상 파일명>' -e '<오류명>' -- <경로>`로 해당 단서가 적힌 교훈을 찾습니다. `rg` 종료 코드 1은 일치 없음입니다. 권한 오류나 `rg` 종료 코드 2 이상이면 교훈 조회를 멈추고 원래 작업을 이어갑니다.
2. 일치 파일의 첫 줄을 확인해 활성 후보만 추립니다. 모델에 전달하는 활성 후보 목록과 본문 발췌는 각각 50줄과 8KiB 이내로 제한합니다. 발췌는 적용 조건과 다음 행동부터 확인하고 근거가 필요할 때 범위 안에서 추가합니다. 범위를 넘거나 적용할 교훈이 없고 근거 있는 대체 검색어가 있으면 같은 범위에서 한 번만 다시 검색합니다. 결과를 줄이지 못해 프로젝트 조회를 마칠 수 없으면 공통 조회도 보류합니다.
3. 일치한 파일 중 첫 줄이 `status: active`인 후보의 적용 조건과 다음 행동을 대조합니다. 현재 코드·계약·환경·버전에 맞는 근거가 있어야 적용합니다. 같은 조건에 상충하는 후보가 있으면 현재 근거로 유효한 행동을 확인하고, 판단할 수 없으면 적용을 보류합니다. 관련 후보를 대조한 뒤 적용할 프로젝트 교훈이 하나라도 있으면 그 범위에서 조회를 끝냅니다. 프로젝트에 적용할 교훈과 미해결 충돌이 모두 없을 때만 `shared`를 같은 방식으로 조회합니다. 새 단서가 생기기 전에는 같은 검색을 반복하지 않습니다.
4. `review`와 `retired`는 상태 관리에 필요할 때 확인합니다. `review`는 진단에 참고할 수 있으며, 재현이나 직접 증거로 확인해 `active`로 되돌린 뒤 해결책으로 재사용합니다. `retired`는 이력 확인에만 사용합니다.

## 기록과 정리

기본 저장 위치는 `project`입니다. 여러 프로젝트에서 통하는 조건과 근거를 확인한 경우에만 `shared`에 저장하고 프로젝트 고유 정보는 제거합니다. 비밀값, 개인정보, 원문 로그를 저장하지 않습니다. 제목이나 적용 조건에 다음 작업에서 검색할 실제 파일명·오류명·도구명 중 관련 단서를 넣습니다. 같은 파일 이름을 쓰기 전에 기존 내용을 확인합니다.

```markdown
status: active

# 교훈을 찾을 때 검색할 짧은 제목

- 발생 조건과 적용 범위 — 오류·도구·버전·환경 중 판단에 필요한 조건
- 확인 결과와 근거 — 관찰한 결과와 다시 확인할 방법. 가설은 따로 표시
- 다음에 할 행동 — 먼저 확인할 항목과 건너뛸 시도
- 마지막 검증일 — YYYY-MM-DD 또는 미검증
- 변경 이력 — 갱신·폐기 시 날짜, 사유, 대체 교훈 경로(있을 경우)
```

- `active`는 적용 조건과 방법을 확인한 상태입니다. 미검증 관찰을 남길 가치가 있다면 `review`로 기록합니다.
- 동일 조건의 교훈은 중복 생성 전에 기존 기록을 확인합니다. 더 나은 방법이 검증되면 기존 파일의 행동과 근거를 갱신하고 이유를 남깁니다. 예전 방법이 구버전에서 계속 유효하면 범위를 좁히고 새 방법은 별도 조건으로 기록합니다.
- 오래됐거나 환경이 달라진 기록은 조회·정리 시 재검토합니다. 새 증거와 충돌하거나 확인 근거가 부족하면 `review`로 바꾸고 필요한 확인을 적습니다. 재검증되면 `active`로 되돌리고 검증일을 갱신합니다.
- 적용할 조건이 사라졌거나 완전히 대체됐다면 `retired`로 바꾸고 사유와 대체 경로가 있다면 그 위치를 남깁니다. 통합으로 대체된 중복도 같은 방식으로 처리합니다. 상태와 사유는 같은 파일에서 함께 수정합니다.
