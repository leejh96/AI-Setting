# 구현 이유 설명

“왜 별도 경로를 쓰지?”, “왜 이 검사가 먼저야?”처럼 기존 결정을 묻는 질문에 답합니다. 현재 동작만 묻는 질문은 관련 코드 흐름으로 설명합니다. 설명 요청은 읽기 전용으로 진행합니다.

## 지금 동작과 결정의 이력 확인

1. 현재 코드에서 질문의 대상과 실제 동작을 확인합니다. 호출부나 테스트는 선택의 영향이나 유지할 계약을 이해하는 데 필요할 때 읽습니다. 작업 트리와 커밋된 내용이 다르면 이력이 어느 쪽을 설명하는지 확인합니다.
2. `git log -S`로 관련 값이나 식별자가 들어오고 사라진 시점을, `git log -G`로 관련 줄이 바뀐 시점을 찾습니다. `git blame`은 커밋을 찾는 단서로 쓰고, `git show`로 당시 변경과 메시지를 확인합니다. 파일 이동이나 기계적인 정리가 이력을 가리면 이전 경로나 이름을 좁혀 봅니다. 이유를 설명할 근거가 확보되면 탐색을 마칩니다.
3. 커밋이 무엇을 바꿨는지만 보여주면 연결된 PR·이슈·설계 문서·당시 테스트에서 어떤 문제나 제약이 선택을 이끌었는지 확인합니다. 이후 변경이나 현재 계약에서 그 제약이 여전히 적용되는지 대조합니다. 기록에 나오는 대안과 비용은 질문에 관련 있을 때만 다룹니다.

## 답변

- 왜 이 방식을 썼는지 먼저 쉬운 말로 답합니다. 근거가 된 커밋·PR·문서와 현재 코드 위치를 가까이에 붙입니다.
- 당시 이유가 기록되어 있으면 출처를 밝힙니다. 변경 내용이나 테스트에서 추정한 내용은 근거와 함께 추정이라고 씁니다. 기록이 없거나 접근할 수 없으면 확인한 범위와 알 수 없는 부분을 짚습니다. 커밋 제목이 변경 사실을 확인해 주더라도 선택 이유는 따로 확인합니다.
- 당시 제약이 지금도 유효한지, 변경하면 어떤 기존 동작에 영향이 있는지는 근거가 있을 때 설명합니다.
