# 개발 작업 진행과 완료 확인

개발 요청의 목표와 후속 정정에 맞춰 필요한 작업을 처리하고, 완료 조건과 검증 결과를 확인합니다. 작업 추적을 위해 `TASKS.md` 같은 별도 파일을 만들지 않습니다. 사용자가 요청한 기능 문서나 기존 문서의 수정은 이 제한에 포함되지 않습니다.

## 작업 정리와 진행

- 요청과 관련 코드·계약을 필요한 범위에서 확인해 완료 조건과 작업을 정합니다. 새 기능은 요구 동작, 기존 기능 수정은 바뀔 동작과 유지할 동작, 버그 수정은 실패 경로, 리팩터링은 유지할 외부 동작을 확인합니다. 검증도 필요한 작업에 포함합니다.
- 작업 크기에 맞춰 나눕니다. 한 단계로 끝나는 단순한 작업은 별도 목록이나 진행 절차를 생략할 수 있습니다. 분석·리뷰만 요청받았다면 그 범위에서만 진행하고 코드를 수정하지 않습니다.
- 여러 단계라면 실행 전에 필요한 작업과 각 상태를 사용자에게 목록으로 보여줍니다. 현재 작업은 `진행 중`, 아직 시작하지 않은 작업은 `대기`로 표시합니다. 다음 작업에 착수하기 전에 목록을 갱신해 그 작업을 `진행 중`으로 표시하고, 앞선 작업의 상태와 남은 작업도 함께 보여줍니다. 작업이 완료되거나 보류될 때와 전체 종료 전에도 해당 상태를 갱신합니다.
- 작업 계획 도구가 제공되면 그 도구로 목록과 지원되는 상태를 갱신합니다. 도구가 없으면 대화 메시지에 목록을 표시하고 갱신합니다. 도구가 `보류` 등 필요한 상태를 지원하지 않으면 해당 작업의 상태와 사유를 대화 목록에 표시합니다. 문장으로 순서만 설명하는 것은 작업별 상태 표시를 대신하지 않습니다.
- 작업이 진행되며 필요한 항목을 추가하거나 불필요해진 항목을 이유와 함께 제외합니다. 사용자 요청과 후속 정정에 따른 목표·범위를 보존하고, 목록을 끝내기 위해 요구사항을 임의로 축소하지 않습니다.
- 요구사항이나 권한 때문에 막힌 항목은 보류 사유를 남기고 필요한 확인을 요청합니다. 그 결정과 무관하게 진행할 수 있는 작업은 계속합니다.

## 상태와 완료 판단

- 각 작업을 대기·진행 중·완료·보류로 관리합니다. 완료는 해당 작업과 필요한 검증을 마친 경우에만 표시하고, 구현만 끝났거나 검증하지 못했다면 이를 구분합니다. 검증 결과와 보류 사유를 필요한 만큼 함께 기록합니다.
- 대화가 압축된 후 이어갈 때 원래 목표, 남은 작업, 완료·검증 상태와 보류 사유를 확인합니다. 상태가 불분명하면 현재 코드와 확인 가능한 대화·검증 결과를 대조해 복원하고, 복원할 수 없는 중요한 내용은 질문합니다. 확인되지 않은 상태를 완료로 추정하지 않습니다.
- 마무리 전에 원래 요청과 후속 정정을 작업 결과에 대조하고, 새로 발견된 필수 작업과 필요한 검증이 남았는지 확인합니다. 모든 필수 작업과 검증을 마쳤을 때만 전체 완료로 보고합니다. 실패·미검증·보류가 있으면 완료한 부분과 남은 사유를 구분해 보고합니다.
