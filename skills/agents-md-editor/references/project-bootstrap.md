# 프로젝트 지침 처음 작성하기

프로젝트에서 자주 쓰는 표현과 실제 코드·실행 방법을 연결해 다음 작업의 반복 탐색을 줄입니다. 사용자가 프로젝트 지침의 작성이나 보강을 요청했을 때 적용합니다.

## 대상과 기존 근거 확인

- 작성할 저장소와 도구가 읽는 지침 경로를 확인합니다. 기존 `AGENTS.md`, 우선 적용 파일, README, 관련 개발 문서·템플릿·manifest·lockfile·CI·테스트 설정과 같은 책임의 대표 구현을 필요한 범위에서 확인합니다. 전체 코드베이스를 일률적으로 읽지 않습니다.
- 루트의 `AGENTS.md`가 다른 환경에 배포할 전역 원본인지 확인합니다. 전역 원본에 해당 저장소의 용어·명령을 섞거나, 이름만 보고 프로젝트 지침으로 덮어쓰지 않습니다. 사용할 별도 프로젝트 경로가 정해지지 않았고 작성이 필요하면 질문하며, 위치 결정과 무관한 사실 정리는 진행합니다.
- 기존 지침이 있으면 유효한 내용과 사용자 변경을 보존하면서 요청한 부분만 보강합니다. 초기 작성 요청을 기존 지침 전체 교체 권한으로 해석하지 않습니다.

## 남길 정보

필요한 항목만 짧게 작성합니다. 단순한 프로젝트라면 50줄 내외를 목표로 하되 중요한 조건·예외를 생략하는 제한으로 사용하지 않습니다.

| 항목 | 확인하고 기록할 내용 |
| --- | --- |
| 프로젝트 목적 | 무엇을 제공하는 저장소인지, 이번 지침이 적용되는 범위 |
| 용어와 코드 연결 | 사용자가 실제로 쓰는 용어·약어, 그 의미, 관련 클래스·테이블·API·경로 |
| 주요 책임 경계 | 자주 수정하는 진입점, 해당 위치의 책임, 넘지 않아야 할 경계 |
| 공통 규칙과 반복되는 틀 | 확인된 네이밍·파일 배치·공통 응답·예외 처리·테스트·문서 형식 등의 적용 범위, 예외와 대표 경로 |
| 실행·검증 | 작업 디렉터리, 프로젝트가 사용하는 패키지 관리자·런타임, 작업별 실제 명령과 전제 조건 |
| 작업 제약 | 외부 서비스·실데이터 사용 여부, 생성 파일, 유지할 계약 등 근거가 있는 제약 |
| 추가 자료 | 어떤 작업에서 어느 기존 문서를 읽으면 되는지 짧은 연결 |

- 사용자 용어는 기존 문서나 확인된 사용자 발언을 근거로 기록합니다. 코드 이름만 보고 사용자가 그렇게 부른다고 추측하지 않습니다. 모호한 용어는 미확정으로 분리하고 실제로 작업 판단을 막을 때 질문합니다.
- 반복되는 틀은 같은 책임의 구현과 관련 문서·설정·템플릿을 대조해 확인합니다. 기존 공통 규칙과 형식은 반드시 유지하고, 앞으로 같은 종류의 작업에서도 따를 수 있도록 적용 범위·예외·대표 경로를 남깁니다. 단일 사례를 프로젝트 전체 규칙으로 확대하거나 모양만 비슷한 코드를 같은 틀로 단정하지 않습니다. 관찰된 관례를 새 업무 규칙의 확정 근거로 삼지 않으며, 서로 다른 관례가 충돌하면 그 차이와 미결정 사항을 분리합니다.
- 실행 명령은 README·manifest·CI 등에서 확인한 값과 작업 디렉터리를 함께 기록합니다. 명령의 존재 확인과 실행 성공을 구분하고, 필요한 실행 확인을 못 했으면 사유를 남깁니다. 무거운 빌드·외부 서비스 호출·설치·배포를 지침 작성만을 위해 임의로 실행하지 않습니다.
- 비용·보안·업무 결과를 바꾸는 정책을 관례로 만들지 않습니다. 확인되지 않은 항목은 사실처럼 적지 않으며, 재사용 가치가 있는 미결정 사항만 남깁니다.
- 전역 협업 원칙은 전역 지침 없이도 독립 배포·사용하거나 반복해서 명시할 이유가 있는 경우를 제외하고 복제하지 않습니다. 긴 디렉터리 목록, 매 작업의 진행 상황과 명령 출력은 복제하지 않습니다. 상세 설명은 원래 문서에 두고 필요한 때 읽도록 연결합니다.
- 기기별 개인 절대 경로 대신 저장소 기준 경로와 필요한 환경변수 이름을 씁니다. 비밀값을 기록하지 않습니다.

## 작성 후 확인

- 용어·경로·명령·제약을 근거와 대조하고, 템플릿의 빈 항목을 채우기 위해 정보를 만들어 넣지 않았는지 확인합니다.
- 기존 공통 규칙과 반복되는 틀의 적용 범위·예외가 작성·축약 후에도 유지되는지 대조합니다. 상세 문서로 연결한 경우에도 지침에서 그 규칙을 언제 따라야 하는지 알 수 있어야 합니다. 규칙 자체의 변경이 필요하면 근거와 달라지는 행동을 설명하고 해당 변경에 대한 사용자 요청·확인 범위 안에서 진행합니다.
- 선택한 경로가 사용하는 도구와 실행 위치에서 읽히는지 확인합니다. 하위 지침 파일을 만들었다는 이유만으로 루트에서 시작한 대화에도 자동 적용된다고 주장하지 않습니다.
- 변경 내용과 실행·미실행 검증을 구분해 보고합니다. 지침 작성과 실제 도구 로딩 확인은 별개이며, 전역 설치·다른 도구로의 동기화는 요청 범위를 따릅니다.
