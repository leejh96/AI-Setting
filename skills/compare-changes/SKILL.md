# 변경 전후 비교

사용자가 같은 상황에서 어떤 차이를 보거나 겪는지 보여줍니다. 사용자가 지정한 형식을 따르고, 형식이 정해지지 않았으면 차이를 가장 쉽게 확인할 수 있는 자료를 선택합니다.

## 수정 전에 비교할 상태 확인

- 핵심 차이가 드러나는 화면, 입력, 조작 또는 업무 조건을 고릅니다. 비교에 필요한 데이터, 화면 크기, 권한이나 실행 환경은 양쪽에서 맞출 수 있게 확인합니다.
- 실행 자료가 필요하면 손대기 전의 실제 작업 상태에서 화면, 응답·데이터 상태, 측정값 등을 확보합니다. 기존 미커밋 변경이 있더라도 비교를 위해 작업 트리를 되돌리지 않습니다. 코드나 설정만으로 설명할 수 있는 변경은 관련 경로와 현재 동작을 확인하면 충분합니다.

## 변경 후 같은 조건으로 비교

실행 자료가 필요한 경우 변경 전과 같은 조건에서 결과를 확인합니다. 이미 확보한 실행 결과나 검증 자료는 재사용합니다. 비교 조건을 맞추기 어렵거나 전후 자료 중 일부만 확보했다면 그 범위와 이유를 밝힙니다. 코드·설정에서 파악한 동작과 실제 실행으로 확인한 결과를 구분합니다.

| 보여줄 차이 | 비교 방법 |
| --- | --- |
| 화면 배치·스타일 | 같은 화면과 데이터 상태에서 찍은 전후 스크린샷을 각각 표시합니다. 나란히 볼 수 있으면 같은 크기로 배치하고, 작은 변경은 같은 영역을 확대합니다. |
| 클릭·전환·입력 흐름 | 같은 조작을 담은 짧은 녹화나 단계별 캡처를 사용합니다. 결과가 갈리는 동작을 짚습니다. |
| API·업무 규칙 | 같은 입력에 대한 전후 응답과 필요한 경우 최종 데이터 상태를 보여줍니다. 조건이 여럿이면 조건별로 표에 정리합니다. |
| 처리 순서·구조 | 바뀐 단계와 연결을 짧은 흐름도나 순서 목록으로 보여줍니다. |
| 성능·비용 | 같은 조건으로 얻은 측정값을 단위와 함께 비교합니다. 추세나 분포가 중요하면 그래프를 사용합니다. |
| 단순한 동작·설정 | 핵심 차이를 한 문장이나 짧은 실행 예시로 설명합니다. |

## 최종 보고에 보여주기

핵심 차이를 먼저 짚고, 자료에 `변경 전`과 `변경 후`를 표시합니다. 이미지나 영상은 대화에서 표시할 수 있으면 직접 보여주고, 그 외에는 열어 볼 수 있는 파일이나 링크를 붙입니다. 여러 형식은 각각 다른 차이를 설명할 때 함께 사용합니다.

## 비교 자료 저장과 정리

- 비교 파일의 기본 위치는 현재 도구가 읽는 스킬 설치 폴더 아래 `artifacts/YYYY-MM-DD-<작업ID>/`입니다. 사용자가 저장소 밖의 위치를 지정하면 그 위치를 우선합니다.
- 스킬 폴더가 저장소 안에 있거나, 기본 경로에 쓸 수 없거나, 답변에서 파일을 열 수 없으면 허용된 저장소 밖의 전달 위치 아래에 `compare-changes/artifacts/YYYY-MM-DD-<작업ID>/`를 사용합니다. 도구가 작업용 파일의 위치를 고정하면 그 경로를 확인해 두고, 최종 답변에는 실제 전달 경로를 연결합니다.
- 작업 중 만든 자료는 작업 폴더의 `work/`에 모으고, 답변에 보여줄 파일과 별도 보관을 요청받은 자료는 `final/`에 둡니다. 비교 파일은 `before.png`·`after.png`처럼 짝을 맞춥니다. 여러 조건을 비교할 때는 `before-mobile.png`·`after-mobile.png`처럼 같은 접미사를 붙입니다.
- 답변을 보내기 전에 이번 작업에서 만든 미사용 캡처·녹화, 중복본, 로그를 권한 범위에서 정리합니다. 전용 브라우저 프로필은 사용을 마친 뒤 정리합니다. 최종 링크를 확인하고, 정리하지 못한 파일은 경로와 이유를 알립니다. 보관 기한이나 삭제 시점을 지정받았으면 따릅니다.
